# Window Peek

macOS 原生菜单栏工具：长按 Command，横向查看**当前应用**的窗口缩略图，按编号选中，松开切换。使用 SwiftUI、AppKit、ScreenCaptureKit 和辅助功能 API；窗口编号桥接的兼容性说明见下方。

## 运行

需要 macOS 14 或更新版本。当前构建脚本生成本机架构的应用（这台机器为 Apple Silicon）。

```bash
./scripts/build-app.sh --install
open "$HOME/Applications/Window Peek.app"
```

`--install` 将签名后的应用复制到当前用户的 `~/Applications/Window Peek.app`，避免同步工程目录的 Finder 元数据影响安装包。更新前退出正在运行的 Window Peek；以后始终打开这个固定位置的应用。省略 `--install` 则只生成 `dist/Window Peek.app`。应用启动后常驻菜单栏，点击编号窗口图标进入设置或退出。

菜单栏列表顶部的“启用窗口切换”可直接开启 / 停用：打勾表示启用，再点一次即可停用，不会打开设置页。该状态与设置页同步，重启后保留；停用会关闭预览并停止快捷键监听。

首次打开设置页，依次开启：

1. **辅助功能**：监听快捷键、获取应用窗口、切换目标窗口。
2. **屏幕与系统音频录制**（部分系统叫“屏幕录制”）：获取窗口缩略图。应用不采集音频、不写入截图文件、不上传画面。设置中的“刷新权限”可重新检查；系统要求重启时，请退出后重新打开应用。

未开启屏幕录制也可以切换窗口，只显示标题和预览占位。辅助功能权限必须开启。

返回应用、打开菜单或点击“刷新权限”会重新检查授权；手动复查使用同一个已签名程序的短时子进程读取状态，不弹出授权请求、不截图。当系统已授权但当前进程仍未生效时，显示“已授权 · 需重启”，点击“重新启动”即可。设置页关闭后停止两秒轮询，后台不再持续刷新权限。

构建脚本优先使用钥匙串中已有的 Developer ID Application 证书，也可通过 `WINDOWPEEK_SIGN_IDENTITY` 指定签名身份。证书与 bundle ID 保持一致可让系统持续识别后续版本；从旧的临时签名切换到固定签名时，可能需要最后重新授权一次。没有可用证书才回退到 ad-hoc，并打印说明。

应用图标已包含在 `.app/Contents/Resources/WindowPeek.icns` 中，构建完成会刷新 Launch Services 注册；不需要再做 DMG 才有图标。系统授权列表若保留旧的无图标条目，可先关闭再打开系统设置；若条目已失效，需要用户在系统设置中移除旧条目、重新添加当前 `.app` 并授权。不要直接运行 `.build` 里的裸可执行文件进行授权。

## DMG 安装包

运行 `./scripts/build-dmg.sh`，生成 `dist/WindowPeek-0.3.0-arm64-Installer.dmg` 及 SHA-256 校验文件。脚本必须使用 Developer ID Application 证书，为应用启用 Hardened Runtime 并添加安全时间戳，同时签名 DMG；构建后会校验映像并挂载检查应用签名和安装入口。安装窗口使用专属背景和固定左右布局，将左侧应用拖到右侧 Applications 即可，不再附带安装说明 TXT。首次打包会在 `.build/dmg-tools` 创建隔离的 Python 环境并安装布局依赖。

打开 DMG，将应用拖到 Applications。若已经安装在 `~/Applications`，请先退出旧版本并替换原位置，避免多个副本；不要直接从 DMG 启动应用。打包不会自动修复系统中旧签名对应的录屏授权记录。

公证时显式指定本次安装包，避免提交旧文件：

```bash
./scripts/notarize-dmg.sh windowpeek-notary dist/WindowPeek-0.3.0-arm64-Installer.dmg
```

需要先在本机钥匙串配置公证凭据。脚本在等待前保存提交编号；等待中断后可在同一命令末尾追加该编号继续。公证通过后附加票据、验证并重新生成校验文件。GitHub Release 与 Apple 公证是两个独立步骤。

## 应用内更新

从 0.3.0 起，应用运行期间默认每天检查更新；菜单栏和设置中也可以手动检查。发现新版本后由用户确认下载、安装和重新启动，可在设置关闭自动检查。0.2.2 及更早版本需手动安装一次。

版本号统一维护在 `Updates/config.json`。维护者提交并推送代码后运行 `python3 scripts/release.py --publish`，自动完成构建、公证、上传与更新清单发布。详细步骤、钥匙串配置和失败恢复见 [更新与发版说明](Updates/README.md)。

## 操作

| 操作 | 结果 |
| --- | --- |
| 单独长按左 / 右 Command | 默认长按 0.25 秒后开始准备窗口预览 |
| 持续按住 Command，按 1–9 | 选中对应编号，松开 Command 切换 |
| 持续按住 Command，按 ← / → | 前后循环选择，选中窗口自动滚动到视野内 |
| Command + ` | 立即显示预览并选择下一个窗口，可连续按 |
| 松开 Command / 按 Return | 确认当前选择 |
| Esc / 点击面板外部 | 取消切换 |
| 点击预览卡片 | 立即切换该窗口 |
| Command+C、Command+Tab 等其他组合键 | 收起预览，让原应用 / 系统正常处理 |

上方显示 1–9 快捷键，每张卡片左上角显示自己的编号。超过 9 个窗口时使用方向键或横向滚动查看；当前前台窗口优先排在第一位。触发时间可在设置中改为 0.15 / 0.25（默认）/ 0.4 / 0.6 秒。

以上操作以默认 Command 为例。设置中的“激活键”支持 **Command / Option / Control / Shift**；更改后立即生效，重启后保留选择。长按、松开确认和“激活键 + 反引号”都使用所选按键，界面说明同步更新。左右两侧的同名修饰键都支持；额外按下其他修饰键会取消预览。

外接 Windows 键盘的 Win 键通常映射为 Command；若你的键盘做过修改，请先到 macOS 键盘设置中确认修饰键映射。应用不单独监听未经映射的 Windows 按键。

## 预览与兼容性

- 每次打开时获取窗口快照，最多两张并发，优先选中窗口和当前可见窗口；滚动或选择其他窗口会调整待处理顺序。截图限制为 672×426 以内，关闭面板后取消任务并释放画面；不是持续播放的视频。
- 快速读取窗口时，先确定面板尺寸，再给首屏截图最多 120 毫秒准备时间，准备完成即可提前显示，减少加载文字和图片之间的闪动；窗口枚举超过 250 毫秒才显示整体加载提示。面板显示后保持尺寸不变，截图在固定区域内直接显示，不播放缩放或淡入动画。松键、取消或点击其他窗口会一并取消待显示面板。
- 列表尚未读完时会保留选择及松键确认，最多等待 1.2 秒。新按键、鼠标操作或切换应用会取消延迟确认，避免稍后意外抢回焦点。
- 面板显示在鼠标所在屏幕，支持横向滚动和全屏空间的辅助浮层。
- 过滤非主窗口、非焦点、非模态且不在普通窗口层的辅助面板，避免一个窗口被显示成两个；正常窗口和最小化窗口不会因缺少预览被隐藏。
- 窗口列表来自应用公开的辅助功能接口；最小化窗口若可枚举，选择后会尝试恢复。预览优先按真实系统窗口编号对应，Chrome 同名、同位置窗口也不依赖当前前台窗口。编号必须属于当前应用且未被其他条目使用。
- 窗口编号通过运行时加载的 `_AXUIElementGetWindow` 未公开系统接口获取，封装在 `WindowIdentityBridge.swift`。该接口没有 Apple 的兼容性保证；符号不存在或调用失败时，回退到位置、大小和标题匹配（兼容 Chrome 标题后缀），仍有歧义则保留占位。已返回的编号失效或不属于当前应用时，不改配其他窗口。
- 部分应用、受保护内容、最小化窗口或其他空间中的窗口可能无法提供截图。窗口不能唯一匹配时显示“暂时无法预览”，避免用错画面；仍用原始辅助功能窗口对象切换。
- 系统安全输入、应用不支持辅助功能、权限撤销或目标窗口关闭，都可能导致快捷键 / 切换失败。切换失败时会提示音，并在设置页显示原因。
- 数字快捷键对应主键盘数字行 1–9；当前不含小键盘数字、Shift 反向循环、任意组合键录入或登录自动启动。

## 开发与验证

```bash
swift test
./scripts/verify-previews.sh
./scripts/build-app.sh
open "dist/Window Peek.app" --args --demo
```

`./scripts/verify-previews.sh` 检查 1 / 3 / 9 个窗口从加载到逐张截图显示及空列表的面板尺寸，不需要读取其他应用。

`./scripts/verify-previews.sh --chrome` 额外复测真实 Chrome 窗口：先打开至少两个未最小化的窗口，脚本会依次将它们置前，核对全部预览与原窗口的对应关系，再尝试恢复原窗口顺序和前台应用。它还会模拟编号桥接不可用及部分窗口回退的情况；需要辅助功能与录屏权限，不记录标题、网页地址或截图文件。

演示模式使用程序绘制的示意缩略图，不读取其他应用、不申请系统权限。演示面板支持方向键选择、Esc 关闭，只注册一份监听。以 `--demo` 启动时，通过菜单栏退出应用，再正常启动即可使用真实窗口模式。

源码结构：

- `Sources/SwitcherCore/`：按键状态机、延迟选择、可取消后台工作及预览调度。
- `Sources/WindowPeek/KeyboardMonitor.swift`：全局事件监听与延迟触发。
- `Sources/WindowPeek/WindowService.swift`：辅助功能窗口枚举、快照、前台切换。
- `Sources/WindowPeek/SwitcherUI.swift`：横向预览面板和编号卡片。
- `Sources/WindowPeek/SettingsView.swift`：权限引导和设置。
- `Sources/WindowPeek/PermissionService.swift`：当前进程与新进程的只读权限复查。
- `Sources/WindowPeek/AppDelegate.swift`：菜单栏、生命周期和异步加载。

32 项自动测试覆盖按键状态变化、加载期间松键、取消传递、截图并发上限与重排、迟到结果丢弃、权限需重启状态，以及辅助窗口过滤、窗口编号匹配、失效编号与兼容回退、Chrome 标题后缀与重名歧义。测试不替代授权后的系统集成验证。建议授权后在 Finder / Safari 等应用中打开三个窗口，检查数字选择、松键切换、最小化恢复、Command+Tab 放行、双屏和全屏场景。

预览诊断使用系统日志的 `local.windowpeek.app` 子系统、`Preview` 分类，记录匹配数量和截图错误码，不记录窗口标题、网页地址或截图内容。

API 参考：[Apple ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager)、[辅助功能窗口操作](https://developer.apple.com/documentation/applicationservices/1462091-axuielementperformaction)。
